## 2. Цель работы

Расширить MVP приложения единым контрактом фильтрации на backend и UI-фильтрами на frontend, усилить CRUD-сценарии (create/edit/view/delete), а также повысить безопасность файловых операций в MinIO (ограничения типов/размера, безопасная выдача, отказоустойчивость при удалении).

## 3. Исходное состояние проекта

- До начала ЛР3 в проекте уже были реализованы RBAC (ЛР1) и token-auth (ЛР2).
- Списковые endpoint-ы возвращали массивы без унифицированной пагинации.
- В админ-панели были доступны create/delete, но не было полноценного edit.
- Object storage работало без pre-signed URL и с более мягкими ограничениями upload.

## 4. Постановка задачи

Требования из `LABS_BACKLOG/LAB3_FILTERS_CRUD_STORAGE.md`:

- унифицировать backend-контракты фильтрации (`search`, `sortBy`, `sortDir`, `page`, `pageSize`, предметные фильтры);
- внедрить frontend фильтры + сохранение состояния в query params;
- расширить CRUD: create/edit/view/delete с валидацией и обработкой `400/403/404/409`;
- усилить object storage: MIME whitelist, лимит размера, безопасная выдача, удаление файла и метаданных, устойчивость к частичным сбоям;
- сохранить совместимость с RBAC/auth и игровым flow.

## 5. Проектные решения

- Выбран единый формат списковых ответов: `{ items, total, page, pageSize }`.
- Для фильтров применен общий подход:
  - `search` (по релевантным полям),
  - сортировка (`sortBy`, `sortDir`),
  - пагинация (`page`, `pageSize`),
  - предметные фильтры (например, `floorId`, `building`, `level`, `minScore`, `role`).
- CRUD-валидация разделена:
  - клиентская — до отправки (обязательные поля, базовая целостность формы);
  - серверная — окончательная (корректность id/координат, обязательные поля, конфликты `409`).
- Для выдачи файлов выбран pre-signed URL подход:
  - хранение объекта в MinIO;
  - выдача временной ссылки (TTL 300 сек) в API-ответах.

## 6. Реализация

### 6.1 Серверная часть

Изменения в `server/src/index.js`:

- Добавлены унифицированные утилиты:
  - парсинг/ограничение целых параметров;
  - обработка sort direction;
  - формирование `{ items, total, page, pageSize }`;
  - валидация обязательных текстовых полей;
  - валидация image upload (MIME + размер).
- Обновлены endpoint-ы списков:
  - `GET /api/floors` — фильтры `search/building/level` + sort + pagination;
  - `GET /api/locations` — фильтры `mode/search/floorId` + sort + pagination;
  - `GET /api/leaderboard` — фильтры `search/minScore` + sort + pagination;
  - `GET /api/admin/users` — фильтры `search/role` + sort + pagination.
- Расширен CRUD:
  - добавлен `PUT /api/floors/:id` (редактирование этажа);
  - добавлен `PUT /api/locations/:id` (редактирование локации);
  - в create/update введены проверки и конфликты `409`:
    - дубликат этажа по (`building`, `level`);
    - дубликат локации по (`floor_id`, `x`, `y`, `is_360`).
- Улучшена отказоустойчивость удаления:
  - `DELETE /api/floors/:id` и `DELETE /api/locations/:id` продолжают бизнес-удаление даже при неуспешной очистке объекта в MinIO;
  - в ответ добавляется массив `warnings` для частичных сбоев.
- Добаван middleware для ошибок `multer` (`LIMIT_FILE_SIZE` -> `400` с понятным текстом).

Изменения в `server/src/storage.js`:

- Добавлена генерация pre-signed URL через `@aws-sdk/s3-request-presigner`.
- Удаление объекта теперь выбрасывает ошибку наружу (решение о реакции принимает бизнес-слой).
- Инициализация bucket переведена на private-доступ с безопасной выдачей через подписи.

### 6.2 Клиентская часть

Изменения в `client/src/pages/Admin.tsx`:

- Добавлены state-параметры фильтрации и пагинации:
  - `search`, `sortBy`, `sortDir`, `page`;
  - синхронизация с URL query params через `useSearchParams`.
- Реализованы loading/error/empty состояния.
- Добавлено редактирование (edit) для этажей и локаций:
  - prefill формы по кнопке «Редактировать»;
  - сохранение через `PUT` endpoint;
  - клиентская валидация обязательных полей.
- Добавлена пагинация в UI для списков.

Изменения в `client/src/pages/LeaderboardPage.tsx`:

- Добавлены `search`, `sortDir`, `page` с сохранением в query params.
- Лидерборд переведен на пагинированный контракт backend.

Изменения в API-слое:

- `client/src/shared/api/leaderboard.ts`: контракт `getLeaderboard(params)` -> `{ items, total, page, pageSize }`.
- `client/src/shared/api/game.ts`: адаптация `getFloors()` под новый формат списков (`response.items`).

### 6.3 Данные и инфраструктура

- Добавлена серверная зависимость: `@aws-sdk/s3-request-presigner`.
- Изменения внесены без миграций схемы БД (использована существующая структура).

## 7. Проверка и тестирование

### Позитивные проверки

- Фильтрация/поиск/сортировка/пагинация работают на:
  - `floors`,
  - `locations`,
  - `leaderboard`,
  - `admin/users`.
- CRUD:
  - create floor/location — успешно при валидных данных;
  - edit floor/location — успешно с сохранением изменений;
  - delete floor/location — удаляет запись и пытается удалить файлы из storage.
- Безопасная выдача:
  - `image_path` в ответах списков/карточек выдается как short-lived pre-signed URL.

### Негативные проверки

- `400`:
  - отсутствие обязательных полей;
  - неверные координаты;
  - неподдерживаемый MIME;
  - превышение лимита размера файла.
- `403`:
  - сохраняются RBAC-ограничения на create/update/delete/manage.
- `404`:
  - update несуществующей сущности.
- `409`:
  - конфликт по дубликату этажа или координат локации.

### Техническая проверка сборки

- `client`: `npm run build` — успешно.
- `server`: `node --check src/index.js` — синтаксически корректно.
