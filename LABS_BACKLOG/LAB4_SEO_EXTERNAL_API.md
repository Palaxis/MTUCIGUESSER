# ЛР4 - SEO оптимизация и интеграция стороннего API

## Цель

Добавить SEO-оптимизацию публичных страниц и надежную интеграцию внешнего API без изменения ключевой бизнес-логики игры.

## Зависимости

- Требует ЛР1-ЛР3.
- Все новые разделы должны учитывать права доступа и auth-состояния.

## Границы лабораторной

- Делать: meta/semantic SEO, sitemap/robots, статусы, performance, third-party API.
- Не делать: построение полного тестового контура и CI/CD (это ЛР5-ЛР6).

## Бэклог задач (выполнять по порядку)

1. **SEO-аудит страниц**
   - разделить страницы на публичные и приватные;
   - определить индексируемые и закрытые от индексации URL.
2. **Frontend SEO**
   - семантическая разметка (`title`, `h1-h3`, `alt`, логичная структура блоков);
   - динамические meta-теги для ключевых страниц;
   - canonical URL;
   - OpenGraph теги.
3. **Backend техническое SEO**
   - `GET /sitemap.xml`;
   - `GET /robots.txt`;
   - корректные HTTP статусы для ошибок и недоступности.
4. **Structured data**
   - JSON-LD минимум для одного типа страницы (например, leaderboard/public page).
5. **Оптимизация производительности**
   - lazy loading тяжелых компонентов/медиа;
   - сокращение лишних запросов;
   - оптимизация размера передаваемых ресурсов;
   - отсутствие заметных layout shifts.
6. **Интеграция внешнего API**
   - выбрать use-case (например: подсказки, погодный контекст, геоданные);
   - реализовать adapter/service слой на backend;
   - хранить ключи только в env;
   - добавить timeout/retry/rate-limit;
   - нормализовать ответ в внутренний формат приложения.
7. **Frontend работа с внешними данными**
   - состояния loading/empty/error;
   - graceful degradation при недоступности API.

## Критерии готовности (DoD)

- sitemap и robots доступны и корректны.
- На целевых страницах настроены meta/canonical/OpenGraph.
- Внешний API интегрирован через отдельный слой и безопасно настроен.
- При падении внешнего API интерфейс работает деградируя мягко.
- Игровая логика не изменена и не деградирована.

## Инструкции для Cursor

1. Сначала сделать инвентаризацию URL и стратегию индексации.
2. После этого внедрять SEO-изменения в UI и серверные файлы.
3. Интеграцию внешнего API делать через отдельный service/adapter.
4. Не смешивать секреты с кодом, все ключи через env.

## Промпты для Cursor

### Prompt A - SEO инвентаризация
```text
Составь карту маршрутов приложения:
1) публичные индексируемые,
2) публичные неиндексируемые,
3) приватные.
Предложи SEO-стратегию для каждой группы и список целевых страниц.
```

### Prompt B - Реализация SEO
```text
Реализуй SEO-улучшения:
1) корректная семантика и заголовки;
2) динамические title/description;
3) canonical и OpenGraph;
4) sitemap.xml и robots.txt на backend.
Сохрани текущую логику приложения.
```

### Prompt C - Интеграция внешнего API
```text
Добавь интеграцию стороннего API через backend adapter/service.
Реализуй timeout, retry и нормализацию ответа.
Ключи конфигурации вынеси в env.
На frontend покажи loading/empty/error и graceful degradation.
```

### Prompt D - Верификация
```text
Проверь:
1) доступность sitemap/robots;
2) корректность meta/canonical на целевых страницах;
3) поведение UI при отказе внешнего API;
4) отсутствие регрессий в основном игровом сценарии.
```

3. JSON-LD пример и обоснование.
4. Описание интеграции внешнего API и нормализации данных.
5. Протокол проверки отказоустойчивости внешнего API.
6. Подтверждение сохранения игровой функциональности.
