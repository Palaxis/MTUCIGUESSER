# ЛР6 - Контейнеризация и автоматизация деплоя

## Цель

Подготовить воспроизводимую контейнерную среду и автоматизированный процесс сборки/проверки/доставки приложения с сохранением функционала MVP и доработок ЛР1-ЛР5.

## Зависимости

- Требует завершенных ЛР1-ЛР5.
- Нельзя упрощать/удалять ранее реализованную безопасность и тесты.

## Границы лабораторной

- Делать: Dockerfile, compose, proxy, env-management, healthchecks, CI/CD.
- Делать: подтверждение воспроизводимости старта и устойчивости.

## Бэклог задач (выполнять по порядку)

1. **Архитектура контейнеров**
   - определить состав сервисов: frontend, backend, db, object storage, reverse proxy;
   - описать сеть, порты, volume и взаимодействие.
2. **Dockerfile и .dockerignore**
   - отдельный Dockerfile для backend;
   - отдельный Dockerfile для frontend (build + runtime);
   - корректные `.dockerignore` для сокращения контекста сборки.
3. **Reverse proxy**
   - настроить Nginx/Caddy/Angie:
     - статика frontend,
     - проксирование API,
     - корректные заголовки и базовые security settings.
4. **docker-compose orchestration**
   - запуск всей системы одной командой;
   - настроить env, volumes, networks, ports;
   - healthchecks для критичных сервисов;
   - порядок старта по готовности зависимостей.
5. **Безопасная конфигурация**
   - вынести конфиги в env;
   - исключить секреты из репозитория;
   - добавить `.env.example` для воспроизводимости.
6. **CI/CD pipeline**
   - на PR/commit: lint + tests + build images;
   - при успехе: publish артефактов/образов;
   - deploy на целевую среду после проверок.
7. **Failover sanity checks**
   - зафиксировать поведение при сбое сервиса;
   - проверить восстановление и корректность ошибок.

## Критерии готовности (DoD)

- Приложение поднимается локально одной командой.
- Все ключевые сервисы проходят healthcheck.
- CI пайплайн запускает обязательные проверки.
- Секреты не попадают в репозиторий.
- После контейнеризации игровой функционал и предыдущие доработки работают.

## Инструкции для Cursor

1. Сначала зафиксируй целевую контейнерную архитектуру.
2. Затем подготовь Dockerfile + compose + proxy.
3. После локальной верификации добавь CI/CD этапы.
4. Обязательно добавить инструкции запуска и восстановления в документацию.

## Промпты для Cursor

### Prompt A - Проект контейнерной архитектуры
```text
Сформируй целевую архитектуру контейнеризации текущего проекта:
сервисы, сети, порты, volumes, healthchecks, зависимости запуска.
Выдай план внедрения по шагам без правок, затем реализуй его.
```

### Prompt B - Docker и compose
```text
Добавь Dockerfile для backend и frontend, .dockerignore и docker-compose
для полного запуска приложения с reverse proxy и зависимостями.
Сохрани совместимость с текущим dev/prod потоком.
```

### Prompt C - CI/CD
```text
Настрой CI/CD:
1) lint + tests + build images;
2) publish artifacts/images;
3) deploy после успешных проверок.
Добавь защиту от утечки секретов и проверку env-конфигурации.
```

### Prompt D - Верификация
```text
Сформируй и выполни чеклист:
1) локальный старт одной командой;
2) healthcheck сервисов;
3) прохождение CI;
4) поведение при падении одного сервиса;
5) отсутствие регрессий игрового функционала.
```
