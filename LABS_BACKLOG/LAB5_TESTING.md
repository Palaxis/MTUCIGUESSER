# ЛР5 - Комплексное тестирование клиентской и серверной частей

## Цель

Построить воспроизводимую систему тестирования (unit/integration/e2e) для подтверждения корректности бизнес-логики, безопасности доступа и устойчивости интеграций.

## Зависимости

- Требует ЛР1-ЛР4.
- Тесты должны покрывать реализованные механизмы RBAC/auth/files/SEO/external API.

## Границы лабораторной

- Делать: тест-модель, unit/integration/e2e, test-infra, coverage thresholds.
- Не делать: деплой и контейнерный runtime как основной фокус (это ЛР6).

## Бэклог задач (выполнять по порядку)

1. **Тест-модель приложения**
   - выделить критичные user flows;
   - выделить high-risk зоны: auth, RBAC, CRUD, файлы, интеграции;
   - зафиксировать приоритеты тестирования.
2. **Backend unit tests**
   - сервисы аутентификации и прав;
   - сервисы бизнес-логики игры;
   - обработка edge cases и валидаций.
3. **Backend integration tests**
   - endpoint-тесты: коды, структура ответов, сценарии отказа;
   - проверка `401/403/404/409` и ошибок валидации.
4. **Frontend unit/scenario tests**
   - компоненты, хуки и утилиты;
   - сценарии форм, навигации, фильтров, role-based UI.
5. **E2E тесты**
   - login/logout/refresh;
   - CRUD по ролям;
   - фильтрация/сортировка/пагинация;
   - upload/download/delete файлов;
   - работа с внешним API в норме и при сбоях.
6. **Тестовая инфраструктура**
   - отдельные test-конфиги;
   - изолированная БД/фикстуры;
   - моки внешних сервисов (object storage, third-party API);
   - очистка состояния между тестами.
7. **Метрики качества**
   - минимальные пороги покрытия (backend и frontend);
   - разделение быстрых и медленных тестов;
   - единые нейминги и структура тестов.

## Критерии готовности (DoD)

- Сформирована тест-пирамида unit/integration/e2e.
- Ключевые бизнес-сценарии покрыты автотестами.
- Поведение RBAC/auth и ошибок подтверждено тестами.
- Внешние зависимости изолированы моками.
- Пороговые метрики покрытия выполняются.

## Инструкции для Cursor

1. Сначала зафиксировать тест-модель и критичные сценарии.
2. Затем настроить инфраструктуру тестов и фикстур.
3. Писать тесты от самых стабильных слоев к более дорогим (unit -> integration -> e2e).
4. После каждой группы тестов фиксировать итог в протоколе.

## Промпты для Cursor

### Prompt A - Тест-модель
```text
Составь тест-модель текущего приложения:
критичные сценарии, бизнес-правила, high-risk области.
Разбей на unit/integration/e2e и приоритеты покрытия.
```

### Prompt B - Backend тесты
```text
Добавь backend unit и integration тесты:
auth, RBAC, CRUD, файловые операции, обработка ошибок.
Используй отдельную test-базу и изоляцию данных.
```

### Prompt C - Frontend и E2E
```text
Добавь frontend unit/scenario тесты и e2e проверки ключевых пользовательских потоков.
Покрой роль-ориентированное поведение UI, фильтры и ошибочные состояния.
```

### Prompt D - Метрики и итог
```text
Настрой пороги покрытия и разделение тестов на fast/slow suites.
Сформируй финальный тестовый протокол:
что покрыто, что не покрыто, остаточные риски.
```

## Отчет по ЛР5 (что обязательно включить)

1. Тест-модель и карта рисков.
2. Структура тестов (unit/integration/e2e).
3. Конфигурация тестовой инфраструктуры и моков.
4. Ключевые тест-кейсы и результаты прогонов.
5. Метрики покрытия и интерпретация.
6. Остаточные риски и план улучшений.
